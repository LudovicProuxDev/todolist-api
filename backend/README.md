# Backend

REST API built with **Symfony 8.1** and **API Platform 4.4**, on **PHP 8.4** and **PostgreSQL 16**.
Authentication relies on JWT ([LexikJWTAuthenticationBundle](https://github.com/lexik/LexikJWTAuthenticationBundle))
with refresh tokens ([JWTRefreshTokenBundle](https://github.com/markitosgv/JWTRefreshTokenBundle)).

## Configuration

The configuration is read from `.env` (versioned defaults), overridden by `.env.local` (not versioned)
and by the real environment variables.

| Variable | Description |
|---|---|
| `APP_ENV` / `APP_SECRET` | Symfony environment and secret |
| `DATABASE_URL` | PostgreSQL connection. Set by `compose.yaml` for the `backend` container |
| `CORS_ALLOW_ORIGIN` | Allowed origins (regex), `localhost` and `127.0.0.1` on any port by default |
| `JWT_SECRET_KEY` / `JWT_PUBLIC_KEY` | Paths of the JWT key pair (`config/jwt/*.pem`) |
| `JWT_PASSPHRASE` | Passphrase of the private key |

In the container, the database is reached through the `db` service:
`postgresql://root:secret@db:5432/todolist?serverVersion=16&charset=utf8`.

## Setup

The `backend` service of `compose.yaml` runs `composer install`, creates the database, runs the migrations and
starts the PHP built-in server on port 8000. Two steps remain, once.

### JWT keys

The key pair is not versioned. Generate it with the `JWT_PASSPHRASE` of `.env`:

```bash
docker compose exec backend php bin/console lexik:jwt:generate-keypair
```

### First user

Every endpoint of the `User` resource requires authentication, so the first user is created directly in the database:

```bash
HASH=$(docker compose exec -T backend php bin/console security:hash-password 'ChangeMe123!' 'App\Entity\User' -n 2>/dev/null \
  | grep -oE '\$(2y|argon2id?)\$[^ ]+')

docker compose exec -T db psql -U root -d todolist -c \
  "INSERT INTO \"user\" (username, roles, password, lastname, firstname, email)
   VALUES ('admin', '[\"ROLE_ADMIN\"]', '$HASH', 'Admin', 'Admin', 'admin@example.com');"
```

## Database

### Model

| Entity | Fields | Relations |
|---|---|---|
| `User` (table `user`) | `username` (unique), `roles` (JSON), `password` (hashed), `lastname`, `firstname`, `email` | - |
| `Task` | `description`, `createdAt` | Many-to-one to `Category` |
| `Category` | `label`, `color` | - |
| `RefreshToken` | Managed by the refresh token bundle | - |

### Migrations

```bash
docker compose exec backend php bin/console make:migration              # after an entity change
docker compose exec backend php bin/console doctrine:migrations:migrate
```

### Sample data

The fixtures use [Foundry](https://github.com/zenstruck/foundry) stories (`src/Story/`):

```bash
docker compose exec backend php bin/console doctrine:fixtures:load
```

This **empties the database** before loading categories, tasks and 100 users. The generated users have random,
unhashed passwords and cannot log in: recreate your own user afterwards ([First user](#first-user)).

## API

The interactive documentation (Swagger UI) is available at http://localhost:8000/api, and the OpenAPI
specification at http://localhost:8000/api/docs.jsonopenapi.
Resources are served in JSON-LD (`application/ld+json`) by default.
`PATCH` requests use `application/merge-patch+json`.

### Authentication

| Endpoint | Description |
|---|---|
| `POST /api/auth` | Login with `username` and `password`, returns `token` (JWT) and `refresh_token` |
| `POST /api/token/refresh` | Returns a new JWT from a `refresh_token` |

```bash
# Get a JWT and a refresh token
curl -X POST http://localhost:8000/api/auth \
  -H 'Content-Type: application/json' \
  -d '{"username": "admin", "password": "ChangeMe123!"}'

# Call the API with the JWT
curl http://localhost:8000/api/me -H 'Authorization: Bearer <token>'

# Get a new JWT when it expires
curl -X POST http://localhost:8000/api/token/refresh \
  -H 'Content-Type: application/json' \
  -d '{"refresh_token": "<refresh_token>"}'
```

The JWT payload contains the `username` and `roles` of the user (used by the frontend).

### Resources

| Resource | Endpoints | Access |
|---|---|---|
| Users | `GET/POST /api/users`, `GET/PATCH/DELETE /api/users/{id}` | Authenticated |
| Current user | `GET /api/me` | Authenticated |
| Tasks | `GET/POST /api/tasks`, `GET/PATCH/DELETE /api/tasks/{id}` | No restriction configured |
| Categories | `GET/POST /api/categories`, `GET/PATCH/DELETE /api/categories/{id}` | No restriction configured |

### Custom logic

| Class | Role |
|---|---|
| `State\MeProvider` | Returns the authenticated user for `GET /api/me` |
| `State\UserPasswordHasher` | Hashes `plainPassword` on user creation and update, then clears it |
| `Validator\RoleCombination` | Forbids a user to have both `ROLE_ADMIN` and `ROLE_METRICS` |

On creation, `plainPassword` is required (`user:create` validation group).

## Security

Firewalls ([`config/packages/security.yaml`](config/packages/security.yaml)):

| Firewall | Path | Authentication |
|---|---|---|
| `metrics` | `^/metrics/prometheus` | HTTP basic, `ROLE_METRICS` required |
| `main` | Everything else | JSON login on `/api/auth`, then JWT; refresh on `/api/token/refresh` |

The `access_control` rules only require a role on `/metrics/prometheus` (no global rule is enabled).
Access to the API is defined on the resources: the `User` resource requires `IS_AUTHENTICATED_FULLY`, while `Task`
and `Category` have no security expression.

| Role | Usage |
|---|---|
| `ROLE_USER` | Default role of every user |
| `ROLE_ADMIN` | Administrator (inherits `ROLE_USER`) |
| `ROLE_METRICS` | Technical account for Prometheus (inherits `ROLE_USER`) |

## Metrics

The backend exposes Prometheus metrics on `/metrics/prometheus`
([artprima/prometheus-metrics-bundle](https://github.com/artprima/prometheus-metrics-bundle)), stored in APCu,
with the `app_backend` namespace. See [`monitoring/README.md`](../monitoring/README.md).

## Tests and code quality

### Tests

Functional tests of the API (`tests/`), with [Foundry](https://github.com/zenstruck/foundry) to reset the database
and create data. They run on the `todolist_test` database:

```bash
docker compose exec backend php bin/console doctrine:database:create --env=test --if-not-exists   # once
docker compose exec backend vendor/bin/phpunit
```

### Static analysis and coding standards

| Tool | Configuration | Command |
|---|---|---|
| PHPStan (level 6, Doctrine extension) | `phpstan.dist.neon` | `vendor/bin/phpstan analyse` |
| PHP-CS-Fixer (`@Symfony` rules) | `.php-cs-fixer.dist.php` | `vendor/bin/php-cs-fixer fix --dry-run --diff` |
| Composer audit | - | `composer audit` |

Run them with `docker compose exec backend <command>`. Remove `--dry-run` to apply the PHP-CS-Fixer fixes.
`config/reference.php` is generated by Symfony and excluded from both tools.

## Docker image

[`Dockerfile`](Dockerfile): `php:8.4-fpm-alpine` with the `intl`, `pdo_pgsql`, `zip`, `opcache` and `apcu`
extensions (APCu is enabled for the CLI, used by the metrics) and Composer.
The `compose.yaml` service mounts the sources in `/var/www/html` and starts the PHP built-in server on port 8000.
